# dup-remover

Учебный проект на **Rust** для команды из двух человек: утилита поиска файлов
с одинаковым содержимым. Программа рекурсивно сканирует папку, показывает группы
дубликатов и оценивает объём лишних копий. При необходимости результат сохраняется
в JSON. Файлы не удаляются и не перемещаются.

## Быстрый старт

Понадобятся Rust и Cargo со стабильной поддержкой edition 2024. Проект работает
на Windows и Linux; сборка и тесты проверяются в GitHub Actions для обеих систем.

```sh
git clone https://github.com/Lledely/dup-remover.git
cd dup-remover
cargo build --release --locked
cargo run --release --locked -- scan ./Downloads
```

Вместо `./Downloads` укажите существующую папку. Путь с пробелами заключите
в кавычки. В Windows можно использовать, например, `"C:\Users\Name\Downloads"`.

```sh
# Только файлы от 1 MB, четыре потока, полный отчёт в новый файл
cargo run --release --locked -- scan ./Downloads --min-size 1MB --jobs 4 --output report.json

# Справка по команде и версия
cargo run --locked -- scan --help
cargo run --locked -- --version
```

После сборки бинарник находится в `target/release/dup-remover`
(`target/release/dup-remover.exe` в Windows). В Linux его можно запускать напрямую:

```sh
./target/release/dup-remover scan ./Downloads --min-size 1MiB --output report.json
```

В PowerShell:

```powershell
.\target\release\dup-remover.exe scan "C:\Users\Name\Downloads" --min-size 1MiB --output report.json
```

## Аргументы команды `scan`

| Аргумент | Назначение | По умолчанию |
| --- | --- | --- |
| `<PATH>` | Папка для рекурсивного сканирования | Обязателен |
| `--min-size <SIZE>` | Минимальный размер включительно | `0` байт |
| `--jobs <N>` | Положительное число потоков для хеширования | Доступное системе число потоков |
| `--output <FILE>` | Новый файл для полного JSON-отчёта | Только текстовый отчёт |

Размер задаётся целым неотрицательным числом: `512`, `512B`, `1KB`, `1MB`,
`1GB`, `1KiB`, `1MiB` или `1GiB`. Суффиксы не зависят от регистра.
`KB/MB/GB` используют множитель 1000, а `KiB/MiB/GiB` — 1024.
Дроби, пробелы внутри значения, неизвестные единицы, переполнение и `--jobs 0`
отвергаются до начала сканирования.

## Результат

Текстовый отчёт содержит количество и общий размер просканированных файлов,
число групп дубликатов, количество лишних копий и их объём в байтах. Для каждой
группы показаны размер, BLAKE3-хеш и пути всех файлов. Если часть файлов не удалось
прочитать, в конце отчёта будут предупреждения с путями и причинами.

В группе из трёх одинаковых файлов два считаются лишними: оценка предполагает
сохранение одного файла в каждой группе. Выбор файла для сохранения остаётся
за пользователем.

JSON содержит всю структуру `ScanReport`:

- `scanned_files` и `scanned_bytes` — количество и размер обычных файлов,
  прошедших фильтр минимального размера, включая файлы с ошибками чтения;
- `duplicate_groups` — группы с полями `size_bytes`, `hash` и `paths`;
- `warnings` — предупреждения с полями `path` и `message`.

`--output` создаёт файл **после завершения сканирования** и никогда не перезаписывает
существующий файл. Для повторного запуска укажите новое имя отчёта.
Текстовый отчёт выводится и при сохранении JSON.

Коды завершения: `0` — успешное сканирование (в том числе с предупреждениями),
справка или версия; `1` — ошибка сканирования или записи/вывода отчёта;
`2` — неверные аргументы. Сообщения о критических ошибках выводятся в stderr.

## Как устроен поиск

1. Обход папок собирает обычные файлы, подходящие по размеру. Символические
   ссылки не обходятся.
2. Файлы группируются по размеру: разные размеры сразу исключают совпадение.
3. Для кандидатов одного размера потоково вычисляется BLAKE3; файлы не загружаются
   целиком в память. Хеширование выполняется параллельно с ограничением `--jobs`.
4. Совпавшие размер и хеш образуют группу. Группы, пути и предупреждения сортируются,
   чтобы результат не зависел от порядка обхода и числа потоков.

Неверная или недоступная корневая папка останавливает запуск. Ошибки отдельных
записей становятся предупреждениями, и сканирование остальных файлов продолжается.

### Ограничения первой версии

Сканирование не фиксирует снимок файловой системы: изменение файлов во время
запуска может повлиять на результат. Совпадение определяется размером и
криптографическим хешем без дополнительного побайтового сравнения.
Жёсткие ссылки учитываются по отдельным путям; объём лишних копий — логическая
оценка, которая не учитывает общие блоки, сжатие и особенности файловой системы.
Пути с невалидным UTF-8 доступны в текстовом отчёте с заменой символов, но не могут
быть сохранены в JSON. Удаление файлов, интерактивный интерфейс и индикатор прогресса
могут стать следующими задачами.

## Разработка и проверки

```sh
cargo fmt --all -- --check
cargo clippy --locked --all-targets --all-features -- -D warnings
cargo test --locked --all-targets
```

Тесты проверяют движок на временных папках и реальные запуски CLI: поиск групп,
фильтры, JSON, справку, неверные аргументы и защиту исходных файлов от перезаписи.
Общий API библиотеки описан в [docs/architecture.md](docs/architecture.md).

Работа разделена между двумя участниками:

| Участник | Задача |
| --- | --- |
| Движок сканирования | [Issue #1](https://github.com/Lledely/dup-remover/issues/1): обход папок, группировка, хеширование, параллельность и тесты библиотеки |
| CLI и отчёты | [Issue #2](https://github.com/Lledely/dup-remover/issues/2): аргументы, текстовый и JSON-отчёты, документация и тесты бинарника |

Для каждой задачи сначала создаётся issue с критериями приёмки, затем отдельная
ветка и PR в `master`. PR ссылается на issue через `Closes #номер`. После ревью
и успешных проверок PR вливается через **Rebase and merge**, а issue закрывается
автоматически. Зависимую ветку перед финальными проверками обновляют через
`git fetch origin` и `git rebase origin/master`.
