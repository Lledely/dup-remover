# Правила проекта

## Git и GitHub

- Основная ветка: `master`.
- Перед реализацией создавать issue с описанием задачи и критериями готовности.
- Для каждого issue создавать отдельную ветку и отдельный PR.
- В случае логической громоздкости реализации на одно issue можно создавать несколько PR. Для каждого PR использовать отдельную рабочую ветку.
- Названия веток: `<номер-issue>-<название>`.
- Формат коммитов: `[#<номер-issue>][label-ы]: ...`. Использовать метки соответствующего issue; например, `[#7][documentation]: Add project development rules`.
- В описании PR указывать изменения, результаты проверок и `Closes #<номер-issue>`.
- Если одно issue реализуется несколькими PR, в промежуточных PR указывать `Refs #<номер-issue>`, а `Closes #<номер-issue>` — в PR, который завершает задачу.
- Изменения в `master` вносить через PR.
- Сливать PR способом Rebase and merge после успешного CI.
- После вливания PR удалять его рабочую ветку локально и на GitHub.
- Изменения в PR дробить на небольшие логические коммиты.
- Способ разработки — test driven development (TDD). Перед написанием кода фичи сделать отдельный коммит с тестами для этой фичи. Сначала убедиться, что новые тесты не проходят из-за отсутствующей реализации, затем реализовать фичу и добиться прохождения тестов.

## Rust

- Перед PR запускать:

  ```text
  cargo fmt --check
  cargo clippy --locked --all-targets -- -D warnings
  cargo test --locked --all-targets
  ```

- При изменении поведения обновлять документацию.
- Добавлять тесты для нового поведения и исправляемых ошибок.

## Общение

- Описания issue и PR писать на русском.
- Названия PR писать на английском.
- Формат названия PR: `[#<номер issue>] <реализуемая фича>`.
- Сообщения коммитов писать на английском.
